  and the tool's contract was narrower than its description implied.

  failed.

## Fixes

1. Code — `search_code` accepts a comma-separated list of globs (split on
   `,`, strip, ignore empties; a file matches when any glob matches its name
   or its relative path). Docstring and the `search_code` description and
   `glob` parameter text in `guru/domain/tools.py` now say "one or more
   globs, comma-separated (e.g. '*.py,*.md')". Tests in
   `tests/test_files.py` (`test_search_code_glob_list_*`).
   Targets: explain-readme; any case where the model narrows a search to
   several file kinds (find-symbol, logic-bug, security-only,
   review-multi-file).
2. Case — `evals/cases/explain-readme.toml`: replaced
   `answer_contains = ["rollback"]` with
   `answer_regex = ["previous (tag|release|version)", "database"]` (the
   planted facts: redeploy the previous tag, do not roll back the database;
   `answer_contains = ["previous tag"]` alone would be brittle to wording).
   `tools_used_any` is now `["read_file", "search_code"]`: a search that
   hits the README is as valid as reading it. The rubric is unchanged.
   This edit does not make the case pass on the recorded run: the recorded
   answer matches neither regex. Targets: explain-readme.
