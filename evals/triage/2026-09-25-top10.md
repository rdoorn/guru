## Findings

1. **Rubric judge and the proxy's thinking budget.** All rubric calls in
   the fast x3 runs errored: the judge asked for 300 output tokens and the
   proxy answers 400 (`max_tokens must be greater than
   thinking.budget_tokens`) for Haiku. `LiteLLMAdapter.complete()` now
   always sends the adapter ceiling (16384); a cap is not a spend. The gate
   reviewer on Sonnet had worked with 400 because the budget is per model
   on the proxy. Verified: run 871dc26f9efa, logic-bug graded 2/2.
2. **The Haiku rubric judge grades harder than the hand grades** (6/6 for
   these cases on 2026-09-24). It sees the answer text only. For the
   version-flag case it gave 0/2 "no code changes shown, no test code
   shown" although the fixture's tests pass and `files_changed` has both
   files: the answer legitimately did not paste the diff. Follow-up: put
   the observed evidence (files changed, fixture tests pass, tools used,
   gate verdicts) into the grading packet, and compare Haiku with Sonnet
   as grader on ten hand-graded answers before trusting `--rubric-min`.
3. **Caching threshold.** Haiku 4.5 caches only prefixes above 4096 tokens
   (Sonnet 1024, Opus 512). The controller prompt plus the controller's
   tool schemas cross it; a worker with few tools may not, which is why
   the share is 29% on the long real cases (more uncached worker input)
   and ~45% on the fast ones.
4. **Panel security worker** did not fire in these runs: no case is a
   review of a whole codebase with the panel point active in this eval
   routing file (`claude-tiers-judges.toml` keeps `panel` in shadow). The
   default block written on first run has it active; measure with
   `review-multi-file` once a routing file with `panel = true` exists.
